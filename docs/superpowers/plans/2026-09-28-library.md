## Global Constraints

- Python 3.12. 테스트: 저장소 루트에서 `.venv/bin/python -m pytest <파일> -q`.
- `library.py` 는 표준 라이브러리만 import 한다 (GUI, yt_dlp 금지).
- 화면 문구는 한국어, 이모지 금지. spec 에 적힌 문구는 글자 그대로.
- 요청받은 파일만 고친다. 옆 코드의 모양을 바꾸거나 정리하지 않는다. 기존 스타일을 따른다.
- 커밋하지 않는다. git 상태를 바꾸는 명령을 쓰지 않는다.
- 마이크·스피커를 쓰지 않는다 (오디오 스트림을 열지 않는다). 유튜브에 접속하지 않는다 (테스트는 가짜 info 와 가짜 파일로).
- 테스트를 약하게 만들어 통과시키지 않는다. 동작이 바뀌어 기존 테스트의 기대값이 달라지면, 새 동작을 검증하도록 고치고 무엇을 왜 바꿨는지 보고한다.

## L1 library.py

**Files:** Create `library.py`, `tests/test_library.py`.

spec 의 "`library.py`", "목록 규칙", "색인 규칙" 을 그대로 구현한다. 설정 함수 4개는 지금 `main.py` 29~55행에 있는 것과 동작이 같아야 한다 (이 작업에서는 `main.py` 를 고치지 않는다. 복사해 온다).

**Tests:** spec "검증" 의 단위 테스트 항목 전부. 최소한:
1. library_dir: 일반 폴더 → `<폴더>/Splitwave`, 이름이 `splitwave`/`Splitwave` 인 폴더 → 그대로. ensure_library 가 폴더를 만든다. library_dir 는 만들지 않는다.
2. base_dir: last_dir 가 있는 폴더면 그것, 없는 폴더거나 키가 없으면 default_download_dir().
3. list_songs: 확장자 필터(대문자 확장자 포함), 점으로 시작하는 파일 제외, 하위 폴더 안 파일 제외, 최신순(os.utime 으로 시각 지정), 없는 폴더 → [].
4. list_tracks: 곡+스템 묶음 순서, 스템만 있는 묶음, 빈 스템 폴더 무시, 묶음 최신순, 스템 label 형식.
5. menu_labels: 순서 유지, 긴 곡 이름 줄이기(길이 정확히 max_len), 스템 라벨에서 스템 이름 보존, 겹치는 이름에 (2).
6. video_id: spec 의 다섯 형태 + 추가 매개변수(`&t=10s`, `?si=...`) + 유튜브가 아닌 주소 → None + 재생목록 주소에 v 가 있으면 그 ID.
7. downloads_from_info: 단일, 재생목록(entries 에 None 섞임), 파일이 없는 항목 제외.
8. record_download / find_downloaded: 왕복, 같은 파일 두 번 기록해도 한 번, 파일을 지우면 find 에서 빠짐, 보관함 밖 경로 무시, 깨진 색인 파일 → 빈 색인으로 동작하고 다음 기록이 성공, 색인 파일 내용 형식.

## L2 main.py, stems_page.py

**Files:** Modify `main.py`, `stems_page.py`, `tests/test_stems_page.py`, `tests/test_app_tabs.py`(필요하면). Create `tests/test_library_gui.py`.

**Consumes:** L1 의 `library` 모듈 전부.

- `main.py` 의 설정 함수 4개를 지우고 `from library import config_path, load_settings, save_settings, default_download_dir` 로 바꾼다 (이름은 그대로 `main` 에서 쓸 수 있어야 한다).
- `App.save_dir` 는 지금처럼 **저장 폴더**다. `App.library_dir` (property) 가 `ensure_library(self.save_dir)` 를 돌려준다.
- `App.library_listeners: list` 를 두고, 보관함 내용이 바뀌면(다운로드 완료, 분리 완료, 저장 폴더 변경) 등록된 콜백을 인자 없이 부른다. `App.notify_library_changed()`.
- 기존 `folder_listeners` 콜백에는 이제 보관함 경로를 넘긴다 (스템 탭의 폴더 글자가 보관함 경로를 보여 주게).
- 나머지는 spec "다운로드 탭", "스템 분리 탭".
- 키 조정이 있을 때 색인에는 조정본(최종 파일)을 기록한다. 기존 동작(원본 삭제)은 그대로.

**Tests (tests/test_library_gui.py, 디스플레이 없으면 skip, 기존 `_make_app` 방식):**
설정 파일이 실제 사용자 설정을 건드리지 않게 `library.config_path` 를 tmp_path 로 monkeypatch 하고 저장 폴더를 tmp_path 로 둔다.
1. 보관함에 가짜 오디오 파일 2개를 두면 스템 탭 드롭다운 값이 안내 항목 + 두 곡(최신순).
2. 드롭다운에서 곡을 고르는 콜백을 부르면 `file_path` 가 그 경로, `resolve_input()` 이 ("file", 경로).
3. `지우기` 뒤 드롭다운이 안내 항목으로 돌아간다.
4. 빈 보관함이면 `(받은 곡이 없어요)`.
5. `notify_library_changed()` 뒤 새 파일이 드롭다운에 나타난다.
6. 이미 받은 링크: `find_downloaded` 가 파일을 돌려주게 하고 `messagebox.askyesno` 를 False 로 monkeypatch → `on_download_click` 이 작업 스레드를 시작하지 않는다 (busy 가 False 그대로). True 면 시작한다 (스레드 시작은 `threading.Thread` 를 monkeypatch 해서 확인, 실제 다운로드 금지).
7. 다운로드 outtmpl 과 스템 결과 폴더가 보관함 아래인지 (yt_dlp.YoutubeDL 과 separator.separate 를 가짜로 바꿔 인자를 확인).

## L3 tempofollow/app.py

**Files:** Modify `tempofollow/app.py`. Create `tests/test_tempofollow_library.py`.

**Consumes:** L1 의 `library.base_dir`, `library_dir`, `list_tracks`, `menu_labels`.

- spec "템포 추종". 파일을 불러오는 부분(`on_choose_file` 안의 불러오기)을 `_load_file(path)` 로 빼서 파일 선택과 보관함 선택이 같이 쓴다.
- 드롭다운 항목을 만드는 순수 함수를 클래스 밖에 둔다: `library_menu(lib: str) -> dict[str, str]` (안내 항목과 빈 목록 문구 포함하지 않음, `menu_labels(list_tracks(lib))` 그대로) 와 `menu_values(items: dict[str, str]) -> list[str]` (안내 항목 또는 빈 목록 문구를 맨 앞에 붙인 표시 목록).
- `tempofollow/engine.py`, `tempo.py`, `stretch.py`, `selftest.py` 는 고치지 않는다.

**Tests:** 화면 클래스를 만들지 않는다 (sounddevice 장치 조회를 피한다). 순수 함수 두 개를 tmp_path 의 가짜 보관함으로 검증: 곡과 스템이 섞인 목록, 빈 보관함 문구, 안내 항목 위치.
`tempofollow.app` import 자체가 되는지도 확인한다 (customtkinter, sounddevice 가 없으면 skip).
